# P0-D2H RTB zero-artifact recovery protocol

## Scope

This protocol permits one externally authorized identical retry of an RTB attempt that is stale
in `running` state and has no persisted inference or analysis artifact. It is an infrastructure
recovery, not a second result-bearing experiment, prompt revision, threshold change, training
run, or capacity scan.

## Eligibility

Recovery is allowed only when all checks pass:

- the manifest is `running`, has no recorded errors, and is stale for at least six hours;
- neither OFF nor ON raw rows, raw checkpoint, pairs, report, summary, nor audit manifest exists;
- the manifest identity equals the immutable preregistration;
- all preflight hashes, original authorization, source trees, and adapter/source identity remain
  unchanged;
- no prior zero-artifact recovery claim exists, except for idempotently completing an interrupted
  governance adoption of this same claim.

## Authorization and claim

The external authorization binds the output path, run ID, preregistration hash, prior running
manifest hash, original experiment Git revision and lock-file hash, recovery-code hash, and a
single identical retry. The approver must also confirm that the original runtime has terminated.
It explicitly forbids training, prompt or threshold changes, new result cells, and 1/4/8
authorization.

The recovery tool immutably adopts that authorization, writes a recovery claim containing the
zero-artifact evidence, then changes only the manifest state from `running` to `authorized` and
adds recovery provenance. The same run ID and output directory are reused. The audit itself must
still execute the original locked experiment revision and pass its original code-hash check.

## Interpretation boundary

The recovered result, if completed, remains a single RTB diagnostic and cannot reopen CPR-v1 or
authorize training or 1/4/8. No recovery or experimental result has been generated by this
protocol document.
